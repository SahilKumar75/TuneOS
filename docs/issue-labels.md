# Issue Labels

TuneOS issues use labels to make roadmap planning, ownership, and triage clear.

## Area Labels

- `area:data`: Dataset discovery, filtering, recommendation, and ingestion.
- `area:analytics`: Model analysis, charts, visuals, and explainability.
- `area:fine-tuning`: LoRA, QLoRA, training configuration, and tuning workflows.
- `area:model-import`: Hugging Face, GitHub, and local model intake.
- `area:chat`: Chat-assisted workflows and conversational model setup.
- `area:projects`: Project organization, workspace layout, and navigation.
- `area:state`: Client and server state management.
- `area:backend`: APIs, workers, storage, and service orchestration.
- `area:docs`: Documentation, templates, and product specifications.

## Type Labels

- `type:feature`: New product capability.
- `type:enhancement`: Improvement to an existing workflow.
- `type:docs`: Documentation work.
- `type:research`: Investigation or technical spike.

## Priority Labels

- `priority:high`: Required for the first complete product workflow.
- `priority:medium`: Important but can follow the core workflow.
- `priority:low`: Useful after the main platform is stable.
